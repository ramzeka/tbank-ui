# Отчет о тестировании Т‑Банк UI на моках

**24 ноября 2026 года**

Здесь зафиксирован исходный прогон. Итоги после исправлений приведены в документации автотестов. [Повторная проверка отчёта](../tests/qa/README.md#повторная-проверка-отчёта)

Проверены все 47 комбинаций HTTP-метода и маршрута, описанных в README. Из 35 проверок 29 прошли, 6 выявили дефекты. Основные сценарии прошли через интерфейс, включая полный расчет на виртуальный счет и восстановление этапа после ошибки выплаты. **Платежные сценарии пока не готовы к выпуску.** После потери ответа и перезагрузки страницы повтор платежа или перевода приводит к двойному списанию на моках. При ответе `401` открытая форма редактирования продолжает показывать паспортные данные и адрес.

## Условия проверки

- Текущий рабочий каталог на базе `53a2475`, включая незакоммиченные изменения. Edge 158.0.4370.33 с отдельным профилем, Node.js 24.22.3 и локальный прокси проекта на Windows PowerShell. В тестовом запуске прокси получил отдельный loopback-порт и запускался без автоматического открытия браузера.
- Синтетические данные и серверные сценарии из `tbank-ui-mock-stage-parties.zip`. Использовались текущие файлы `dist` из проекта. Стенд содержит 50 000 бенефициаров, 20 000 пополнений, 20 000 платежей и 241 перевод до начала прогона.
- Для операций записи проверялись ответы, состояние моков и результат в UI. Для сбоев после записи первая операция выполнялась полностью, затем мок возвращал HTTP `502` вместо успешного ответа. Для ошибок до записи мок возвращал заданный статус без изменения данных.

### Сквозные расчеты

- **Выплата на виртуальный счет.** Созданы сделка, этап и участники. Подтверждение, возврат в черновик, повторное подтверждение и проверка выплат завершились успешно. Этап и сделка получили `COMPLETED`. Остаток депонента уменьшился на 22,02 ₽, остаток реципиента вырос на ту же сумму.
- **Нехватка средств и выплата на банковский счет.** Проверка показала недостаток средств и заблокировала завершение с `422`. После идентификации пополнения проверка прошла, этап стал `COMPLETED`, у депонента списалось 122,33 ₽. По этой сделке список платежей остался пустым. Мок моделирует списание и смену статуса этапа, поэтому создание связанного банковского платежа и его дальнейший статус требуют отдельной проверки.
- **Восстановление после ошибки выплаты.** Из этапа с ошибкой открыт связанный платеж. Мок отклонил несуществующий ID реквизитов с `422`. После выбора действующих реквизитов этап завершился. Отдельно проверен повтор платежа из его карточки с переходом к новой попытке.

## Идемпотентность

| Проверка | Результат |
| --- | --- |
| Ответ `502` после записи и повтор без закрытия формы | Один и тот же UUID-ключ и один ID записи для бенефициара, банковских реквизитов, сделки, этапа, реципиента, прямого платежа и перевода. Для платежа и перевода подтверждено однократное списание. |
| Изменение данных после ошибки в открытой форме | Исправленное тело запроса создания бенефициара отправилось с новым ключом. Отдельная успешная операция платежа с тем же телом также получила новый ключ. |
| Повторный и параллельный запросы через прокси | Два одновременных запроса создания бенефициара с одним ключом и телом вернули один ID. Другое тело с тем же ключом дало `409`, отсутствие ключа дало `400`, неверный формат ключа прокси отклонил с `400`. |
| Повтор после перезагрузки или закрытия формы | Подтверждены дубликаты платежа, перевода и бенефициара. Повтор идентификации и повтор завершения этапа на моках защищаются состоянием операции, а повтор выплаты — ID исходного платежа. |

## Безопасность и доступность

- **Сеанс и прокси.** Проверены ошибочный Bearer-токен, истекший JWT, выход, закрытие списка при `401` и отсутствие токена в `localStorage`. Прокси отклонил девять некорректных запросов до обращения к мок-серверу, включая неправильные `Origin` и `Sec-Fetch-Site`, отсутствие метки запуска, неверные заголовки, запрещенный метод и прямой адрес банковского домена. Проверены CSP, `Cache-Control: no-store`, `X-Content-Type-Options` и `Referrer-Policy`. Строка с разметкой в имени отобразилась буквальным текстом. Дефект видимости персональных данных при `401` описан отдельно.
- **Настройки.** Переданы заголовок `bankAccountId` и номер счета в предусмотренных запросах. UI отклоняет внешний HTTP-адрес и короткий номер счета. При отсутствии номера список переводов выводит подсказку без запроса к мокам. При 22-значном номере обзор сообщает, что для выписки требуется 20-значный счет.
- **Клавиатура и узкий экран.** Проверены стрелки и Home для вкладок обзора, Enter и Escape для диалогов, возврат фокуса и доступное имя диалога в дереве доступности Edge. При ширине 320 CSS-пикселей страница платежей помещалась в экран. Таблица прокручивалась горизонтально стрелками на 573 CSS-пикселя, заголовки столбцов имели `scope=col`. Проверка фокуса при серверной ошибке выявила дефект A11Y-03.

## Обзор счета

В проверке DASH-01 прошли периоды 7 и 30 дней, очереди пополнений и ошибок выплат, переходы к карточкам обеих операций. На 20 000 платежей очередь ошибок появилась через 56,3 секунды после открытия вкладки. До появления строк UI выполнил 400 запросов списка по 50 записей.

## Границы результата

Прогон подтверждает поведение текущего интерфейса и локального прокси на выбранных данных. Контракт реального T‑API, сроки хранения ключей, права разных операторов и номинальных счетов, mTLS, асинхронные статусы и фактическое исполнение выплат требуют интеграционного стенда. Проверка доступности охватывала Edge, клавиатуру и дерево доступности браузера. Для оценки по стандарту доступности потребуется отдельный аудит, включая скринридеры и измерение контрастности.
