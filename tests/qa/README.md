# Автотесты Т‑Банк UI на моках

Прогон открывает приложение из текущей папки `dist` в отдельном профиле Edge, запускает штатный локальный прокси Windows PowerShell и поднимает мок API на свободном порту `127.0.0.1`. Все записи и баланс находятся в памяти моков. Для запуска нужны Windows, Node.js 24 и Microsoft Edge. Установка пакетов не требуется.

## Запуск

Выполните команды из корня репозитория в PowerShell.

```powershell
node tests/qa/run.mjs
node tests/qa/run.mjs --filter '^(PAY|TRF|IDEM)-'
node tests/qa/run.mjs --scale
```

- Обычный прогон выполняет сценарии UI и HTTP, включая сверку всех маршрутов.
- `--filter` выбирает проверки по ID. Вход `AUTH-01` выполняется при любом выборе. Для сверки покрытия нужен полный прогон.
- `--scale` проверяет последнюю страницу платежей и обзор на 50 000 бенефициаров, 20 000 пополнений и 20 000 платежей. Прогон занимает около минуты из-за чтения всех платежей для итогового счётчика.

Код выхода `0` означает успешный прогон, `1` означает сбой. При ошибке сценария прогон останавливается и сохраняет состояние интерфейса и трассу локальных запросов. Результат каждого запуска записывается в `tests/qa/.artifacts/run-*/results.json`. В консоли показывается путь к файлу. Временный профиль удаляется после завершения, а папка результатов исключена из Git.

Переменная `TBANK_QA_EDGE` задаёт путь к `msedge.exe`, если браузер установлен вне стандартной папки. В ограниченной среде, где headless Edge завершает работу при запуске дочерних процессов, доступен флаг `TBANK_QA_EDGE_NO_SANDBOX=1`. Он отключает внутреннюю песочницу Edge в отдельном тестовом профиле. Используйте его только для прогона с локальными синтетическими данными.

### Ручной запуск моков

В первом терминале выполните `node tests/qa/mock-server.mjs`. Во втором задайте `$env:TBANK_UI_MOCK_PROXY` равной адресу мока и запустите `.\start.cmd`. Для этого запуска используйте только `TBANK_UI_MOCK_PROXY`. В настройках подключите демонстрационные ID счёта, номер счёта и токен из первого терминала. Для большого набора запустите мок с `--scale`. Остановите процесс мока, чтобы сбросить данные.

## Повторная проверка отчёта

24 ноября 2026 года полный прогон прошёл все 47 проверок и подтвердил покрытие всех 47 HTTP-операций. Проверки `PAY-03`, `TRF-03` и `BEN-05` подтвердили прежний ключ и одну запись после повторной отправки. `SEC-02` и `SEC-03` подтвердили очистку форм при `401`. `INC-02–04` подтвердили сверку результата перед повтором, а `BEN-02` подтвердил перевод фокуса на ошибочное поле.

В исходном прогоне для новой банковской выплаты отсутствовала связанная запись. Теперь `DEAL-03` проходит от пополнения депонента до проверки реквизитов, суммы и статуса связанного платежа в UI. Набор также проверяет вторую страницу реквизитов, несовпадающий ID карточки, повторяющийся курсор выписки, изоляцию ключей по счёту и восстановление чтения после перегрузки прокси.

Масштабный прогон прошёл все три проверки. На 20 000 исходных платежей первые строки очереди ошибок появились за 76 мс после открытия вкладки. Итоговый счётчик загрузился за 57 секунд после 401 запроса, включая страницу с новым платежом, созданным в ходе проверки. Это измерение локального стенда.

### Исправления после аудита безопасности

Полный прогон прошёл **53 из 53 проверок** с покрытием всех 47 HTTP-операций. `SEC-04` проверяет ограничение адреса назначения в UI и в штатном прокси. `SEC-05` подтверждает завершение сеанса при транспортном `401` даже при коде успеха в теле. `SEC-05` и `SEC-06` проверяют очистку форм платежа и реципиента.

`PAY-06` подтверждает сохранение ключа при транспортном `502` с кодом успеха в теле и одно списание при повторе из другой вкладки. `TRF-04` подтверждает однократную отправку при параллельной попытке из двух вкладок. `IDEM-03` проверяет перенос ключа из хранилища прежней версии. Дополнительно проверены режим запуска без прокси, фиксация HTTPS-адреса, отклонение HTTP в боевом режиме и конфликт переменных запуска.

Проверки используют один профиль Edge и синтетические операции. Гарантии боевого шлюза для разных устройств, профилей, истёкшего ключа и финансовых команд без `Idempotency-Key` остаются условием интеграционной проверки.

`SEC-07` проверяет отклонение маршрутов без обращения к моку. `SEC-08` проверяет отображение полей банковских и налоговых реквизитов без дополнительных данных из ответа. `SEC-09` проверяет удаление параметров URL из старых настроек, сохранение ключа и блокировку новой отправки до сверки незавершённой операции. `AUTH-04` проверяет настроенный префикс шлюза для списка бенефициаров, скоринга и выписки.

## Структура

- `*.test.mjs` содержит сценарии по областям. `flows.mjs` содержит общие действия с формами.
- `harness.mjs` поднимает прокси и моки, пишет результаты и сверяет маршруты. `browser.mjs` открывает Edge и управляет формами через DevTools Protocol. Проверки клавиатуры отправляют браузерные события ввода.
- `mocks/` содержит данные и обработчики API. `before()` задаёт ответ до изменения состояния. `after()` заменяет успешный ответ на `502` после записи. В тестах сверяются ответ UI, запрос и фактические изменения моков.

## Границы

Мок моделирует бизнес-правила и переходы статусов для сценариев тестов. Для банковской выплаты тест переводит связанную запись в статус `SUCCEEDED` во внешнем состоянии мока и проверяет отображение нового статуса. Совместимость с реальным T‑API, права разных операторов на банковские счета, mTLS и фактическое зачисление проверяются на интеграционном стенде.

Журнал незавершённых запросов хранит хеши и UUID-ключи в `localStorage` профиля, общие для вкладок по одному адресу приложения. Параллельные записи с одинаковыми данными блокируются через Web Locks. Для разных профилей, устройств и повторов после истечения ключа требуются гарантии шлюза и API. Для сценария идентификации отсутствие ID в списке подтверждает только отсутствие операции среди неидентифицированных. Распределение сверяется отдельно.

Проверки доступности охватывают Edge, клавиатуру и дерево доступности браузера. Полный аудит включает также скринридеры, контрастность и другие браузеры.
